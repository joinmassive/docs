Massive ISP proxies support the SOCKS5 `UDP ASSOCIATE` command ([RFC 1928, section 7](https://www.rfc-editor.org/rfc/rfc1928#section-7)), on the same host, SOCKS5 port, and credentials you use for `CONNECT` (see [Authentication](/isp-proxies/authentication)).

|             |                          |
|-------------|--------------------------|
| SOCKS5 Port | 8000                     |
| Command     | `UDP ASSOCIATE` (`0x03`) |

<Info>
  curl cannot send UDP through a SOCKS5 proxy. Use a client or library that supports SOCKS5 UDP ASSOCIATE (see the [example](#example) below).
</Info>

## How it works

1. Open a TCP connection to the proxy, authenticate, and send `UDP ASSOCIATE`. `DST.ADDR:DST.PORT` in the request can be `0.0.0.0:0`.
2. The reply contains a relay address, `BND.ADDR:BND.PORT`. Send your datagrams, each wrapped in the standard SOCKS5 UDP header (`RSV RSV FRAG ATYP DST.ADDR DST.PORT DATA`), to exactly that address. Replies come back from it with the same header.
3. Keep the TCP connection open while you use the association. Closing it ends the association.

<Warning>
  Use the IP address from the reply as is. Do not resolve the proxy host again for the UDP traffic: it can point to a different server, which does not know your association.
</Warning>

## Sticky sessions

An association uses one exit IP for its whole life. Add a [session identifier](/isp-proxies/sticky-sessions) to keep that same IP across the session's TCP and UDP traffic; without one, each association gets its own IP.

```text
{PROXY_USERNAME}-session-37:{API_KEY}
```

## Limitations

- **Same source IP.** Datagrams must come from the same public IP as the TCP connection; others are dropped. Watch out behind carrier-grade NAT or multi-WAN, where UDP may leave from a different IP than TCP.
- **Timing.** Send the first datagram within 60 seconds of the reply. The association ends when the TCP connection closes or after 2 minutes without traffic either way.
- **One exit IP.** A session's TCP and UDP share one exit IP. If that server goes offline, the association ends — open a new one.
- **Ports and destinations.** Same [restrictions](/isp-proxies/usage-restrictions) as TCP: ports 80 and 443 only, no private or blocked destinations. A datagram that breaks a rule is dropped silently, because SOCKS5 has no per-datagram error.
- **Two-way only, unfragmented.** A destination that never answers receives at most the first 32 datagrams (64 KiB), so one-way UDP does not work; `FRAG` must be zero.
- **Size and encryption.** The SOCKS5 header adds up to 262 bytes, so keep payloads near the QUIC default (~1,200 bytes) and mind your path MTU. Datagrams are not encrypted at the proxy — QUIC and HTTP/3 provide their own encryption end to end.

<Note>
  UDP counts toward your usage like TCP: datagram payload in both directions. SOCKS5 headers are not counted.
</Note>

## HTTP/3 in browsers

Name resolution through the proxy does not return the records that advertise HTTP/3, so a browser loads a site over HTTP/2 first and switches to HTTP/3 on the next load via its `Alt-Svc` header. Test with at least two page loads.

## Errors

If the proxy cannot set up the association, it answers `UDP ASSOCIATE` with an error reply and closes the connection — there is no fallback to TCP.

| Reply  | Meaning | What to do |
|--------|---------|------------|
| `0x02` | Not allowed: auth failed, account blocked, or destination refused | Check credentials and destination; bans apply as for `CONNECT` |
| `0x07` | UDP not available on this connection | Fall back to TCP, or contact support to enable UDP |

## Example

The Python standard library is enough to open an association and frame datagrams; hand the relay socket to a QUIC or HTTP/3 library to send real traffic. The same handshake works in any language.

```python
import socket
import struct

PROXY = ("{PROXY_HOST}", 8000)
USERNAME = b"{PROXY_USERNAME}-session-37"  # keep one exit IP for the association
API_KEY = b"{API_KEY}"


def udp_associate():
    """Authenticate and send UDP ASSOCIATE. Returns (tcp_conn, relay_addr).

    Keep tcp_conn open: closing it ends the association.
    """
    tcp = socket.create_connection(PROXY)

    # Greeting, offering the username/password method (0x02).
    tcp.sendall(b"\x05\x01\x02")
    if tcp.recv(2)[1] != 0x02:
        raise RuntimeError("proxy did not accept username/password auth")

    # Username/password auth (RFC 1929).
    tcp.sendall(b"\x01" + bytes([len(USERNAME)]) + USERNAME
                + bytes([len(API_KEY)]) + API_KEY)
    if tcp.recv(2)[1] != 0x00:
        raise RuntimeError("authentication failed")

    # UDP ASSOCIATE (0x03); DST.ADDR:DST.PORT may be 0.0.0.0:0.
    tcp.sendall(b"\x05\x03\x00\x01\x00\x00\x00\x00\x00\x00")
    reply = tcp.recv(10)
    if reply[1] != 0x00:
        raise RuntimeError(f"UDP ASSOCIATE refused: 0x{reply[1]:02x}")

    relay = (socket.inet_ntoa(reply[4:8]), struct.unpack("!H", reply[8:10])[0])
    return tcp, relay


def encap(host, port, payload):  # wrap a payload for an IPv4 target
    return (b"\x00\x00\x00\x01" + socket.inet_aton(host)
            + struct.pack("!H", port) + payload)


def decap(datagram):  # strip the header from a reply (IPv4 target)
    return datagram[10:]


tcp, relay = udp_associate()
udp = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
udp.settimeout(5)

# Send your QUIC/HTTP3 datagrams to `relay`; replies arrive with the same header.
udp.sendto(encap("104.16.0.0", 443, your_quic_initial), relay)
reply, _ = udp.recvfrom(65535)
payload = decap(reply)

tcp.close()  # ends the association
```
